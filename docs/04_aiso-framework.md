# 04. AI最適化（AIO / AISO）設計

## 前提：投稿は「知識データ」である
AI Search Optimization の本質は、SNS投稿を **知識データ化** すること。
AIに引用・参照されるのは、**構造・因果・再現性** がある投稿。
感情・雑談は（人には効くが）データとしては弱い。

> だから1投稿を **「仮説検証ログ」** として書く。
> 主張 → 根拠（因果）→ 条件 → 再現手順 → 結果、の骨格を持たせる。

---

## 投稿に持たせる構造（最低限）
1. **問題（現場言語）** … 誰の・どの場面の・何が困るか
2. **原因（因果）** … なぜ起きるのか（構造で説明）
3. **再現性（手順 or 条件）** … どうすれば誰でも同じ結果になるか
4. **横断性** … 他業種（道場・治療院…）でも同じか
5. **メタデータ（タグ・スコア）** … 分類と検証結果

---

## メタデータ設計（`content/posts.csv` と対応）

| フィールド | 意味 | 例 |
|---|---|---|
| `id` | 投稿ID | P01 |
| `structure` | 投稿構造タイプ | 問題ラベル型 / 構造分解型 / 再現性型 / 業界横断型 |
| `theme` | テーマ | 予約 / LINE / LTV / 単価 / 集客 / 見た目 / Web設計 / ギフト |
| `field_pain` | 現場言語の痛み（翻訳済み） | 「LINEの予約返信で1日終わる」 |
| `hypothesis` | 検証したい仮説 | 予約のLINE手作業はLTVを下げる |
| `reproducible` | 再現手順の有無 | yes / no |
| `cross_industry` | 横断性 | ジム/道場/ピラティス/治療院 |
| `cta` | 次の導線 | テンプレ配布 / note / 保存 |
| `score_save` | 保存数（後から記入） | — |
| `score_reply` | 返信・引用数（後から記入） | — |
| `verdict` | 検証結果 | 勝ち / 様子見 / 負け |

→ 反応が出たら `score_*` と `verdict` を埋め、**勝ち仮説をテンプレ化→ツール化** に回す。

---

## 4つの投稿構造（AISOで強い順に設計）
| 型 | 何を強くするか | 使いどころ |
|---|---|---|
| **問題ラベル型** | 検索/引用の入口（痛みの言語化） | 認知拡大・共感 |
| **構造分解型** | 因果の明確化（なぜ起きる） | 信頼・権威 |
| **再現性型** | 手順の提供（誰でも真似できる） | リード化・テンプレ導線 |
| **業界横断型** | 一般化（他業種でも同じ） | SaaSの市場提示 |

※ 各型の文面テンプレは `05_post-templates.md`。

---

## マーケットズレ補正（重要）
- マーケ用語（ROAS・CR・LTV…）は**そのまま出さない**。抽象的で現場に刺さらない。
- 現場の本音は「予約を増やしたい」「LINE対応が大変」。
- ルール：**概念で考え、現場言語で書く**。
  - LTV → 「3ヶ月でやめる人を減らす」
  - ROAS → 「広告1万円で何人来たか」
  - CR → 「Web見た人のうち何人が予約したか」
