# 03. プラットフォーム役割設計

各SNSは「同じネタを使い回す場所」ではなく、**役割が違う**。
1ネタを各プラットフォームの言語に翻訳して展開する。

| 媒体 | 役割 | 出すもの | SaaS導線 |
|---|---|---|---|
| **X** | 思考・構造・実験 | 仮説、構造分解、検証ログ | 中（テンプレ配布で誘導） |
| **Threads** | 共感・軽い気づき | 現場あるある、感情、ひとこと | 低（信頼の入口） |
| **Note** | 深掘り・資産 | 手順書、ケース分解、テンプレ本体 | 高（リード→ツール） |
| **Instagram** | 補助・図解 | 構造図、ビフォーアフター、チェックリスト画像 | 中 |
| **YouTube** | 長期教育・権威 | 業務改善の実演、ツール解説 | 高（権威づけ→導入） |

---

## 媒体別の翻訳ルール

### X（軸）
- ここが**思考の母艦**。1投稿＝1仮説。
- 「問題ラベル → 構造分解 → 再現手順」のどれかの型で書く（→ `05_post-templates.md`）。
- スレッドで「検証ログ」を伸ばす。数字・条件・結果を残す。

### Threads（Xの軽量翻訳）
- Xの仮説を、**感情・あるある**に落として1〜2文で。
- 例：X「予約のLINE手作業はLTVを下げる」→ Threads「LINEの予約返信、気づいたら1日終わってない？」
- SaaSには直結しにくい。**信頼の入口**と割り切る。

### Note（資産）
- Xでウケた仮説を**手順書**に展開。テンプレ本体を置く。
- 「読む→ダウンロード→（回らない部分は）ツール」の導線を必ず作る。

### Instagram（図解）
- 構造分解を**1枚図**に。文字より「型」を見せる。
- 保存される設計（チェックリスト/比較表）を優先。

### YouTube（権威）
- 実際にツールや手順を動かして見せる。**長期教育**。
- 検索流入（「ジム 予約 効率化」等）を取りにいく長期資産。

---

## 1ネタの展開フロー
```
現場の違和感
   └─ X       : 仮説＋構造で投げる（反応を見る＝検証）
        └─ Threads : 当たった仮説を「あるある」に翻訳して裾野を広げる
        └─ Note    : 当たった仮説を手順書＋テンプレに資産化
             └─ Instagram : 手順を1枚図に
             └─ YouTube   : 手順を実演し権威化 → SaaS導線
```
